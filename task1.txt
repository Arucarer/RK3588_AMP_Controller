一、AMP相关核心概念与场景分析（前置认知要求）
1. 什么是AMP
AMP（Asymmetric Multiprocessing，非对称多处理）是多处理器架构的一种工作模式，核心特点是多个 CPU 核心独立运行不同的操作系统（或裸机程序），各核心有明确的角色分工与独立的任务空间，核心间通过预设的通信机制（如共享内存、Mailbox、RPMsg 等）实现数据交互与协同，不依赖统一的操作系统调度。
对于 RK3588 开发板而言，其 CPU 采用 8 核异构架构，由 4 个 Cortex-A55 小核和 4 个 Cortex-A76 大核组成。AMP 模式通常表现为 Linux 与 RTOS 分别运行在不同 CPU 核心上，各自承担专属任务。
本项目中，Linux 系统继续运行于大部分 CPU 核心并保持 SMP 多核调度，单独划分一个 Cortex-A55 核运行 FreeRTOS，用于实时任务处理。第一版计划将 cpu_l3（Cortex-A55，MPIDR 0x300）作为 FreeRTOS 独立运行核心。

---
2. AMP的使用场景
· 实时控制与数据处理场景：如工业自动化系统中，Linux 负责界面显示、网络通信、数据存储和复杂业务处理，FreeRTOS 负责电机控制、实时采样、GPIO 中断等实时任务。
· 异构任务协同场景：需要同时运行复杂通用任务与实时任务的场景，如基于 RK3588 AMP 模式实现“Linux 界面显示 + FreeRTOS 实时控制”的智能终端开发、“Linux 网络通信 + FreeRTOS 数据采集”的边缘计算设备开发。
· 高稳定性要求场景：如车载设备、工业设备等，将复杂 Linux 业务与实时控制任务运行在不同 CPU 核心上，通过 CPU、内存及外设资源隔离减少系统之间的相互影响，提高系统稳定性。
· 多核资源利用场景：根据任务需求合理划分 RK3588 多核 CPU 资源，使 Linux 继续发挥多核通用计算能力，同时划分独立 Cortex-A55 核运行轻量级 RTOS，提高多核 SoC 的资源利用效率。
二、实践核心目标
· 掌握 RK3588 AMP 工作模式的核心原理与架构特点，明确 Linux 与 FreeRTOS 的 CPU 核心角色分配逻辑。
· 完成 RK3588 AMP 模式环境搭建与配置，实现 Linux 与 FreeRTOS 在不同 CPU 核心上的独立启动和独立运行。
· 将指定 Cortex-A55 核从 Linux CPU 调度体系中隔离，独立运行 FreeRTOS，其余 CPU 核心继续运行 Linux。
· 完成 Linux 与 FreeRTOS 的任务分配与程序开发，实现不同系统之间的数据通信与协同工作，如 FreeRTOS 负责传感器采集和实时控制，Linux 负责数据显示、网络通信与用户交互。
· 实现基于共享内存、Mailbox 或 RPMsg 的 Linux 与 FreeRTOS 双向通信。
· 排查实践过程中的核心启动失败、镜像加载失败、内存冲突、通信异常、中断异常等问题，形成规范的项目记录与总结，具备 RK3588 AMP 模式的实操与调试能力。

步骤2：U-Boot配置与AMP引导
进入 RK3588 Linux SDK 的 U-Boot 目录：
cd ~/rk3588_linux_sdk/u-boot
启用 Rockchip AMP 支持：
CONFIG_AMP=y
CONFIG_ROCKCHIP_AMP=y
RK3588 不采用手工执行 secondary_cpu_boot 的简单启动方式，而是使用 Rockchip SDK 已提供的 AMP Framework，通过 AMP FIT Image 描述 FreeRTOS 镜像。
创建 FreeRTOS AMP 镜像配置，例如：
freertos {
    description = "rk3588-freertos-a55";

    data = /incbin/("./freertos.bin");

    type = "firmware";

    compression = "none";

    arch = "arm64";

    cpu = <0x300>;

    hyp = <0>;

    load = <0x08400000>;

    boot-on = <1>;

    hash {
        algo = "sha256";
    };
};
其中：
arch = arm64
表示 FreeRTOS 使用 AArch64 架构。
cpu = 0x300
表示目标运行核心为 cpu_l3 Cortex-A55。
FreeRTOS 镜像通过 FIT Image 打包生成：
amp.img
U-Boot 启动 AMP 镜像后，通过 PSCI / SMC 请求 Trusted Firmware 拉起指定 CPU，并跳转到 FreeRTOS 固件入口。
整体启动过程：
U-Boot
↓
amp.img
↓
Rockchip AMP
↓
PSCI CPU_ON
↓
BL31 / Trusted Firmware
↓
Cortex-A55
↓
FreeRTOS

步骤3：Linux内核与设备树AMP配置
1. CPU核心隔离
Linux 不关闭 SMP，而是继续运行于其余 CPU 核心。
通过 RK3588 AMP Device Tree 将 FreeRTOS 使用的 Cortex-A55 核从 Linux CPU 拓扑中移除。
第一版采用：
cpu_l3
Cortex-A55
MPIDR = 0x300
用于运行 FreeRTOS。
设备树配置思想：
cpus {
    cpu-map {
        cluster0 {
            /delete-node/ core3;
        };
    };
};

/delete-node/ &cpu_l3;
使 Linux 不再调度该 CPU，从而实现 Linux 与 FreeRTOS 的 CPU 核心隔离。

---
2. AMP内存划分
使用 Device Tree 对 Linux、FreeRTOS 和核心间通信内存进行划分，避免不同系统同时使用同一物理内存。
Rockchip RK3588 AMP 方案中规划：
AMP共享内存：
0x07800000
大小4MB

RPMsg区域：
0x07C00000
大小4MB

RPMsg DMA：
0x08000000
大小1MB
同时为 FreeRTOS 独立划分固件与运行内存区域。
第一版规划：
FreeRTOS运行区域：

0x08400000
~
0x093FFFFF

大小16MB
Linux 不使用该区域，从而避免 Linux 与 FreeRTOS 发生内存冲突。

3. FreeRTOS配置
FreeRTOS 在一个 CPU 核心上独立运行，因此关闭 FreeRTOS SMP：
#define configUSE_SMP 0
配置任务优先级：
#define configMAX_PRIORITIES 5
配置最小任务栈：
#define configMINIMAL_STACK_SIZE 128
FreeRTOS Tick 使用 ARM Generic Timer，根据系统定时器频率进行配置，不直接将 CPU 主频固定写为 1.5 GHz。
